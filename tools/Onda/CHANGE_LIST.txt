Onda strict UI cleanup refactor

Base source: onda_clean_ui_refactor, which was generated from the uploaded last-working backup.

Rollback point before this pass:
- /mnt/data/onda_clean_ui_refactor.zip

What changed in this strict pass:
- Removed the remaining normal UI-state DOM style mutations for display/show/hide/open/closed states.
- Converted modal, toast, settings popup, playlist detail panel, tags bar, and now-playing mode pill visibility to class-based state.
- Replaced remaining dynamic inline HTML style strings inside JavaScript templates with CSS classes or CSS-variable-backed classes.
- Reworked visualizer colour chips so fixed palette colours use generated CSS classes and custom/runtime colours use a CSS variable.
- Reworked settings popup dragging so JS writes CSS variables instead of direct left/top/transform element properties.
- Reworked library drawer sizing so JS writes CSS variables and state classes instead of direct width/left/right/bottom element properties.
- Moved Cloud Sync responsive rules out of cloud-sync.css and into responsive.css so cloud-sync.css is base component styling only.
- Consolidated responsive.css into grouped media sections instead of many one-rule media blocks.
- Confirmed there are no exact duplicate selectors outside responsive.css.
- Preserved the Netlify function byte-for-byte from the uploaded onda-sync.js.

Known deliberate non-cleanups:
- The app remains a classic-script app, not ES modules, because changing the global runtime model would be a separate high-risk architecture pass.
- Runtime sizing/position/colour values still use CSS custom properties. Those are intentional dynamic values, not patch CSS.
